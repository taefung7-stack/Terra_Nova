## 문제 (사용자 직접 검수에서 발견)

1. **정답이 가장 길어 티남** — 대부분 객관식에서 정답 보기가 오답보다 길어, 학생이 "가장 긴 것"만 고르면 맞음.
2. **Q4 요약문 빈칸 (A)(B) 좌측 쏠림 + 밑줄 없음** — `summary_template`의 `<blank> (A)`가 `______ (A)`로 좌측에 붙고 채울 밑줄 박스가 없음.
3. **한글 띄어쓰기 깨짐** — Q4 등 한글 필드 곳곳에 이중 공백·구두점 앞 공백 등.
4. **본문↔문제 밑줄 불일치** — 함의 추론 Q3 stem이 `left deliberate gaps`를 인용하지만 본문은 `left empty gaps on purpose`이고 `<u>` 밑줄도 없음.
5. **구문(SYNTAX) 페이지 해석이 하단 통합 블록** — 영어를 읽고 바로 해석을 못 봐 가독성 낮음.
6. **단어장 난이도 미달** — 본문에 `vigorously`·`inert` 같은 고급어가 있는데 단어장은 `element`·`column` 같은 중학 기초어 위주.

## 해결 원칙

- **렌더러/CSS는 1회 수정 → 60지문 전체 자동 반영** (이슈 2·5).

- **데이터 수정은 내용 판단 필요 → 병렬 서브에이전트 검수·교정** (이슈 1·3·4·6).

## A. 렌더러 / CSS (코드 1회)

### A1. 구문 페이지 인라인 해석 (이슈 5)
- `render.js`: `translation_ko`를 `[n]` 마커로 분리, 각 문장(index n)의 해석을 매핑.
- `renderSentences`가 각 `.p3-sentence` 안에 영어 행(`.en-row`) **아래** 해석 행(`.ko-row`) 추가.
- 하단 통합 `.p3-translation` 블록 + `textbook.html`의 해당 마크업 제거.
- **가드**: 문장 수 ≠ `[n]` 조각 수면 `console.warn` + 매핑 안 된 문장은 해석 행 생략(빈 줄 대신).
- 데이터 재작성 없음 — 기존 `translation_ko` 그대로 사용.

### A2. Q4 빈칸 (A)(B) 중앙 정렬 + 밑줄 (이슈 2)
- `summary_template`의 `<blank> (A)` / `<blank> (B)` 패턴 인식.
- 렌더 결과: `<span class="sum-blank"><span class="sum-lab">A</span></span>` — 밑줄 박스(`border-bottom`) + `min-width` + 라벨 중앙 정렬.
- 기존 `.summary-template .blank::before{content:"______"}` 좌측 쏠림 제거.
- 라벨이 따로 텍스트로 `(A)`가 또 나오지 않도록, `<blank> (A)` 토큰 단위로 치환.

## B. Validator 규칙 (`tools/validate-content.mjs`)

신규 검사(고등 프로파일 중심):

1. **정답 길이 균형 (이슈 1, WARN)**: 각 `mock_objective`에서 정답 보기 글자수가 (오답 평균 × 1.4) 이상이면서 최장이면 경고. 빌드 차단 안 함.
2. **밑줄 정합 (이슈 4, ERROR)**: stem이 본문 표현을 인용하는 문제(휴리스틱: stem에 `밑줄 친` 포함, 또는 영어 인용구가 있는 함의/어휘 문제)는, 인용된 영어 구가 `page1.body`에 `<u>…</u>`로 존재해야 함. 없으면 차단.
3. **단어장 본문 등장 (이슈 6, WARN)**: `page4.vocab[].word`가 `page1.body`에 (어형 변화 포함) 등장하지 않으면 경고.
4. **한글 띄어쓰기 (이슈 3, WARN)**: 한글 필드에서 이중 공백, 여는 괄호 뒤 공백, 닫는 괄호/구두점 앞 공백, 숫자-한글 사이 비정상 공백 등 패턴 검출 시 경고.

차단(ERROR)은 본문 정합이 깨지는 이슈 4만. 나머지는 작성 유연성을 위해 WARN.

## C. 데이터 수정 (60지문, 병렬 서브에이전트)

지문별로:
